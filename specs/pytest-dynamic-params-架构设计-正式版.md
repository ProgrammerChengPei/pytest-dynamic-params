## 1. 架构概述

### 1.1 项目定位
pytest-dynamic-params 是一个为 pytest 提供动态参数生成和参数化能力的插件，旨在解决 `pytest.mark.parametrize` 的局限性，为测试参数化提供更灵活、更强大的解决方案。

### 1.2 核心价值主张
- **动态性**: 支持运行时动态生成的参数
- **依赖性**: 处理参数间的复杂依赖关系
- **可扩展性**: 支持自定义参数生成器
- **性能优化**: 通过智能缓存和惰性加载提升效率

### 1.3 设计原则
- **与 pytest 原生集成**: 完全兼容 pytest 官方功能
- **模块化设计**: 清晰的功能边界和职责分离
- **渐进式增强**: 在保持向后兼容性的基础上持续优化

### 1.4 技术栈
- **Python**: 3.7+ 支持现代语法特性
- **pytest**: 7.0+ 与最新版本兼容
- **架构模式**: 装饰器模式、依赖注入、插件架构

### 2.1 核心架构决策

```
├─────────────────┤
│  工具与缓存层    │ ← 辅助功能和优化
└─────────────────┘
```

#### 2.1.2 插件式设计 - ✅ 采纳
- 与 pytest 钩子系统深度集成
- 支持标准的插件发现机制
- 与其他 pytest 插件良好兼容

### 2.2 性能优化方案采纳状态

#### 2.2.1 依赖解析系统优化 - ✅ 部分采纳
- **跨文件依赖追踪** - 采纳：支持不同文件中fixture和参数间的依赖关系
- **运行时依赖缓存** - 采纳：避免重复解析相同的依赖关系
- **复杂表达式解析** - 不采纳：保持简单明确的依赖语法，避免过度工程化

#### 2.2.2 缓存系统优化 - ✅ 采纳核心机制
- **多级缓存策略** - 采纳：实现内存缓存和持久化缓存的多级架构
- **缓存键生成优化** - 采纳：使用高效的参数指纹哈希算法
- **缓存失效策略** - 采纳：细粒度的失效机制，仅失效受影响部分
- **分布式缓存支持** - 有条件采纳：保证与pytest-xdist的基本兼容性

#### 2.2.3 参数化处理引擎优化 - ✅ 采纳重构方案
- **职责分离重构** - 采纳：将600+行process方法拆分为4个专责子方法
- **懒加载优化** - 采纳：延迟解析未使用的参数依赖项
- **智能笛卡尔积缩减** - 采纳：基于参数相关性分析减少不必要的组合
- **并行组合生成** - 采纳：利用多核CPU并行生成不相关的参数组合
- **组合优先级调度** - 不采纳：参数重要性的决策依据难以提供
- **增量式处理** - 有条件采纳：仅重新处理受变更影响的参数子图

#### 2.2.4 生成器引擎优化 - ✅ 采纳轻量级方案
- **异步生成器支持** - 采纳：原生支持async/await模式的参数生成器
- **内存管理优化** - 采纳：包括生成器结果对象池复用和对大型参数对象的高效序列化存储
- **生成器结果缓存亲和性** - 采纳：基于CPU缓存优化的数据布局
- **JIT编译生成器** - 不采纳：实现复杂度高，对纯Python生成器收益有限
- **生成器流水线** - 不采纳：串行生成器的并行流水线执行复杂度过高

### 2.3 插件集成策略

#### 2.3.1 Pytest钩子函数优化 - ✅ 部分采纳
- **钩子函数惰性注册** - 采纳：按需注册钩子函数，减少启动开销
- **钩子执行过滤** - 不采纳：通过pytest原生机制已能有效管理
- **钩子结果缓存** - 不采纳：不符合pytest插件设计最佳实践

#### 2.3.2 pytest-xdist集成 - ✅ 有条件采纳
- **分布式依赖解析** - 有条件采纳：通过基础的文件锁机制实现进程间同步
- **智能副本减少** - 不采纳：pytest-xdist已有内置优化机制
- **工作负载均衡** - 不采纳：任务分配应由pytest-xdist自行处理

## 3. 核心组件与模块设计

### 3.1 整体模块架构

```
pytest-dynamic-params/
├── src/dynamic_params/
│   ├── engine/                    # 核心引擎
│   │   ├── dependency_resolver.py  # 依赖解析器
│   │   ├── generator_engine.py     # 生成器引擎
│   │   └── parametrize_processor.py # 参数化处理器（需重构）
│   ├── plugin/                    # 插件集成
│   │   ├── plugin.py              # 插件入口
│   │   └── pytest_hooks.py        # 钩子函数实现
│   ├── public/                    # 公共API
│   │   ├── decorators/            # 装饰器
│   │   └── api.py                 # API函数
│   └── utils/                     # 工具模块
│       ├── cache_manager.py       # 缓存管理
│       ├── decorator_helpers.py   # 装饰器工具
│       └── validation.py          # 验证工具
└── tests/                         # 测试套件
```

### 3.2 核心组件职责

#### 3.2.1 参数化处理器 (ParametrizeProcessor)
- **主要职责**: 处理参数化逻辑，生成测试用例参数组合
- **重构目标**: 将600+行process方法拆分为4个专责子方法
- **关键接口**: process(), _parse_parameters(), _build_dependency_graph(), _resolve_dependencies()

#### 3.2.2 依赖解析器 (DependencyResolver)
- **主要职责**: 解析参数间的依赖关系，处理循环依赖检测
- **技术实现**: 基于有向图的依赖解析算法
- **核心算法**: 拓扑排序、循环依赖检测

#### 3.2.3 生成器引擎 (GeneratorEngine)
- **主要职责**: 管理参数生成器的注册、执行和缓存
- **支持类型**: 同步生成器、异步生成器、惰性生成器
- **性能优化**: 结果缓存、对象池复用

#### 3.2.4 缓存管理器 (CacheManager)
- **主要职责**: 管理多级缓存策略，优化参数生成性能
- **缓存层级**: 内存缓存、持久化缓存
- **失效策略**: 细粒度失效机制

### 3.3 公共API设计

#### 3.3.1 装饰器API
```python
@dynamic_params(param_generator)
@parametrized_fixture(name, generator_func)
def test_function(param1, param2):
    # 测试逻辑
```

#### 3.3.2 编程式API
```python
from dynamic_params import generate_params

params = generate_params(generator_func, count=100)
```

## 4. 性能优化方案与实施优先级

### 4.1 高优先级优化 (★★★★★)

#### 4.1.1 依赖解析性能优化
- **目标**: 提升参数解析速度30-50%
- **关键技术**: 依赖图压缩存储（使用稀疏矩阵存储大型依赖图）、增量式拓扑排序、最长路径缓存
- **采纳状态**: 三个子项全部采纳，与pytest架构设计深度集成
- **实施时间**: 1-2周

#### 4.1.2 算法和数据结构优化
- **目标**: 核心算法效率显著提升
- **关键技术**: 
  - 图算法优化 - 采纳：依赖图压缩存储、拓扑排序优化、最长路径缓存
  - 集合操作优化 
    - 参数组合压缩 - 采纳：使用位图技术压缩参数组合状态
    - 近似算法支持 - 采纳：大规模参数下的采样和剪枝策略
    - 集合运算加速 - 不采纳：对参数化测试场景收益有限
- **采纳状态**: 在架构设计合理性和性能收益之间优化平衡
- **实施时间**: 2-3周

#### 4.1.2 缓存系统优化
- **目标**: 提升缓存命中率40-60%
- **关键技术**: 多级缓存策略、高效哈希算法

#### 4.1.3 ParametrizeProcessor重构
- **目标**: 解决单一职责原则问题
