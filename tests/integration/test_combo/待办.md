## 新增需求（已完成 ✅）
- 使用@pytest.mark.parametrize传递生成器的参数、该参数的生成器之间的映射关系
    示例：
    @param_generator(scope="session") 
    def data_source():
        return get_dynamic_data()

    @param_generator(scope="session")
    def algorithm():
        """算法列表生成器 - session级别"""
        return ["linear", "quadratic", "exponential"]

    @param_generator(scope="function")
    def processor(algorithm):
        return process_with_algorithm(algorithm)

    @param_generator(scope="function")  
    @pytest.mark.parametrize("data", data_source)  
    @pytest.mark.parametrize("processor", processor)  
    def gen_result(data, processor):
        return processor.process(data)

- @param_generator装饰器是必须要用户写的，但是scope不是、而是根据生成器依赖关系自动添加：gen_result 依赖 data 和 processor， processor 依赖 algorithm 生成器，因此取它们中的最小范围

- 根据函数参数名自动查找对应的生成器，删除多级后缀支持，要求生成器A的参数名和该参数的生成器名B必须完全一致，支持A和B不在同一个.py文件里，但B必须在pytest默认能识别的测试文件里。

- 多级链式生成器的含义应该是，生成器A的某个参数依赖生成器B，生成器B的某个参数依赖生成器C，这种链式。

- 生成器不能循环依赖，比如A依赖B，B又依赖A。

-完全删除@use_generators、DynRef、@parametrize_test、@parametrize_generator, 因为链式生成器@param_generator、@parametrize_fixture、原生pytest这3者结合起来已经能实现所有功能。

- examples/下的用例，只需要展示本插件的最新功能，不需要展示本插件的旧版功能、也不需要展示pytest原生功能
