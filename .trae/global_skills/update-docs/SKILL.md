# 更新文档

## 核心原则
- 遵循行业最佳实践
- 根据文档用途的不同，内容应各有侧重
- 确保文档与代码同步更新

### 文档侧重点
- **需求文档**：聚焦于"做什么"
- **设计文档**：聚焦于"怎么做"
- **用户文档**：聚焦于"如何使用"
- **项目文件**：聚焦于"项目配置"

## 工作流程

### 迭代式文档更新流程
```
需求文档 → 架构设计 → 详细设计 → 项目文件 → 代码生成 → 用户文档
  ↑                                  ↓
  └──────────────────────────────────┘
```

1. 需求文档优化
2. 架构设计（可选）
3. 详细设计生成
4. 项目文件生成
5. 代码生成
6. 用户文档生成
7. 循环优化与反馈
8. 提交准备
9. CICD 支持

## 使用方法

### 基本命令
- `更新全部文档` - 启动完整流程
- `更新需求文档` / `更新设计文档` / `更新用户文档`
- `检查文档一致性` - 验证文档间的一致性

### 高级命令
- `更新文档流程 <步骤>` - 执行特定步骤
- `执行文档循环优化` - 处理后续更新影响前面的情况
- `更新受影响文档 <类型>` - 更新受影响的特定文档

## 注意事项
- 注意文档之间的依赖关系
- 循环优化时主动回退检查前面文档
