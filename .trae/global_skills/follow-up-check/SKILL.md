# 后续动作检查技能

## 核心原则
**完成一步后，主动检查并提醒后续动作！**

## 任务与后续动作映射

### 代码修改后

| 完成的动作 | 后续动作 | 需求文档 | 设计文档 |
|-----------|---------|---------|---------|
| 修复代码 Bug | 运行测试、更新 CHANGELOG | ❌ 不需要 | ❌ 不需要 |
| 添加新功能 | 编写测试、更新文档 | ✅ 需要 | ✅ 需要 |
| 重构代码 | 运行测试、检查性能 | ❌ 不需要 | ⚠️ 视情况 |
| 修改 API | 更新文档、检查兼容性 | ❌ 不需要 | ✅ 需要 |
| 修改业务逻辑 | 运行测试、检查边界 | ⚠️ 视情况 | ⚠️ 视情况 |

### 测试相关

| 完成的动作 | 后续动作 |
|-----------|---------|
| 编写新测试 | 运行测试、检查覆盖率 |
| 修复测试失败 | 分析原因、检查影响 |

### 文档相关

| 完成的动作 | 后续动作 |
|-----------|---------|
| 更新 README | 检查示例、检查链接 |
| 更新 CHANGELOG | 检查完整性、检查版本 |

## 检查流程
```
1. 完成用户请求的任务
2. 分析任务类型
3. 查找对应的后续动作列表
4. 向用户提醒需要执行的后续动作
5. 询问用户是否需要执行
```

### 提醒格式
```markdown
## 任务完成
已完成：[任务描述]
## 建议的后续动作
- [ ] [后续动作1] - [原因]
是否需要我执行这些后续动作？
```

## 注意事项
1. **主动检查**：不要等待用户询问
2. **合理建议**：只建议真正需要的后续动作
3. **尊重用户**：询问用户是否需要执行，不强制执行
