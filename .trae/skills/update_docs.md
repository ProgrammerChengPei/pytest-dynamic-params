# 更新文档

## 功能说明

用于自动化更新项目文档，按照特定流程逐步优化和生成各种文档文件，确保项目文档的一致性、完整性和质量。

**核心原则**：
- 遵循行业最佳实践
- 根据文档用途的不同，内容应各有侧重

**文档侧重点**：
- **需求文档**：聚焦于"做什么"，突出业务需求、功能要求、验收标准和风险分析
- **设计文档**：聚焦于"怎么做"，突出技术实现、架构设计、算法实现和性能优化
- **用户文档**：聚焦于"如何使用"，突出使用指南、示例代码和常见问题
- **项目文件**：聚焦于"项目配置"，突出依赖管理、构建配置和发布信息

## 工作流程

### 1. 需求文档优化

- 根据草稿版需求文件，以及后续的提问逐步优化
- 最终形成 `#spec/需求.md`

### 2. 架构设计（可选）

- 根据 `#spec/需求.md`，生成 `#spec/架构设计.md`
- 当架构简单时可省略此步骤

### 3. 详细设计生成

- 如果有 `#spec/架构设计.md`：根据 `#spec/需求.md` 和 `#spec/架构设计.md`，生成 `#spec/详细设计.md`
- 如果没有 `#spec/架构设计.md`：根据 `#spec/需求.md`，生成或更新 `#spec/设计.md`（包含架构设计和详细设计）

### 4. 项目文件生成

- 生成或更新项目文件 `pyproject.toml`, `README.md`,  `docs/STRUCTURE.md`等

### 5. 代码生成

- 生成或更新源码和测试用例
- 运行测试并修复问题

### 6. 用户文档生成

- 生成 `docs/user-guide.md`，提供使用指南
- 生成 `docs/reports-readme.md`，说明测试报告的使用方法

### 7. 优化循环

- 以上步骤可能会经过几轮优化，确保文档的准确性和完整性

### 8. 提交准备

- 最终优化完成后，生成 `docs/reports-summary.md`
- 生成并运行提交相关的文件（如 `CHANGELOG.md`, `pre-commit-config.yaml`）

### 9. CICD 支持

- 确保项目文件符合 CICD 要求，特别是 `.github/workflows/` 目录下的工作流文件
- 验证 `code-quality.yml` 等工作流文件的配置正确性
- 确保测试覆盖率报告能正确生成和上传
- 验证项目在多个 Python 版本下的兼容性
- 确保 pre-commit 检查能正常通过

## 使用方法

### 基本命令

- `更新文档` - 启动完整的文档更新流程
- `更新需求文档` - 仅更新需求文档部分
- `更新设计文档` - 仅更新设计文档部分
- `更新项目文件` - 仅更新项目配置文件部分
- `更新用户文档` - 仅更新用户文档部分
- `更新 CICD 配置` - 仅更新 CICD 相关配置文件

### 高级命令

- `更新文档流程 <步骤>` - 执行特定步骤的文档更新
  例如：`更新文档流程 5` - 执行代码生成步骤
- `检查文档一致性` - 检查所有文档之间的一致性
- `验证文档完整性` - 验证文档是否完整

### 示例使用

```
更新文档
# 启动完整的文档更新流程

更新需求文档
# 仅更新需求文档部分

更新文档流程 7
# 执行优化循环步骤

检查文档一致性
# 检查所有文档之间的一致性
```

## 注意事项

- **目录结构**：执行文档更新前，请确保项目目录结构完整，特别是 `specs/` 和 `docs/` 目录
- **用户输入**：文档更新过程中可能需要用户提供额外信息，如需求细节、设计偏好等
- **测试环境**：执行测试时，确保测试环境配置正确，依赖包已安装
- **文档规范**：提交前请检查所有生成的文档是否符合项目规范和格式要求
- **版本控制**：确保所有文档更改都被正确提交到版本控制系统
- **备份**：在执行大规模文档更新前，建议备份重要文件
- **依赖关系**：注意文档之间的依赖关系，确保更新顺序正确
- **测试覆盖**：运行测试时，确保测试覆盖了所有关键功能
- **CICD 配置**：确保 CICD ，特别是 Python 版本矩阵和测试命令
- 工作流文件配置正确
- **覆盖率报告**：确保测试覆盖率报告能正确生成和上传到代码覆盖率服务
- **跨版本兼容性**：验证项目在多个 Python 版本下的兼容性
- **pre-commit 检查**：确保所有代码和文档更改都能通过 pre-commit 检查
