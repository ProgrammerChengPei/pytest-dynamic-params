# 更新文档

## 功能说明

用于自动化更新项目文档，按照特定流程逐步优化和生成各种文档文件，确保项目文档的一致性、完整性和质量。

### 核心原则
- 遵循行业最佳实践
- 根据文档用途的不同，内容应各有侧重
- 确保文档与代码同步更新
- 保持文档的清晰性和可维护性

### 文档侧重点
- **需求文档**：聚焦于"做什么"，突出业务需求、功能要求、验收标准和风险分析
- **设计文档**：聚焦于"怎么做"，突出技术实现、架构设计、算法实现和性能优化
- **用户文档**：聚焦于"如何使用"，突出使用指南、示例代码和常见问题
- **项目文件**：聚焦于"项目配置"，突出依赖管理、构建配置和发布信息

## 工作流程

### 1. 需求文档优化
- 根据草稿版需求文件，以及后续的提问逐步优化
- 最终形成 `specs/需求.md`
- 确保需求文档包含清晰的功能描述、验收标准和边界情况

### 2. 架构设计（可选）
- 根据 `specs/需求.md`，生成 `specs/架构设计.md`
- 当架构简单时可省略此步骤
- 架构设计应包含系统架构图、模块划分和核心流程

### 3. 详细设计生成
- 如果有 `specs/架构设计.md`：根据 `specs/需求.md` 和 `specs/架构设计.md`，生成 `specs/详细设计.md`
- 如果没有 `specs/架构设计.md`：根据 `specs/需求.md`，生成或更新 `specs/设计.md`（包含架构设计和详细设计）
- 详细设计应包含类结构、函数接口、数据流和实现细节

### 4. 项目文件生成
- 生成或更新项目文件：`pyproject.toml`、`README.md`、`setup.py`、`docs/STRUCTURE.md` 等
- 更新 `.gitignore` 文件，确保忽略规则合理
- 更新 `LICENSE` 文件，确保许可证信息完整
- 确保项目文件符合 PEP 标准和项目规范

### 5. 代码生成
- 生成或更新源码和测试用例
- 运行测试并修复问题
- 更新 `docs/reports-readme.md` 和 `docs/reports-summary.md`
- 确保代码符合 PEP 8 规范和项目编码标准

### 6. 用户文档生成
- 生成 `docs/usage-guide.md`，提供详细的使用指南，包含常见问题和故障排除
- 更新 `examples/` 目录下的示例文件，确保示例代码与最新版本的 API 一致

### 7. 优化循环
- 以上步骤可能会经过几轮优化，确保文档的准确性和完整性
- 检查文档之间的一致性和相互引用
- 确保文档与代码的同步更新

### 8. 提交准备
- 更新 `CHANGELOG.md` 文件，记录项目的重要变更
- 确保变更记录符合 conventional commits 格式
- 检查所有文档的格式和规范

### 9. CICD 支持
- 更新 `.pre-commit-config.yaml` 文件，确保代码质量检查配置正确
- 确保项目文件符合 CICD 要求，特别是 `.github/workflows/` 目录下的工作流文件
- 确保测试覆盖率报告能正确生成和上传
- 验证项目在多个 Python 版本下的兼容性
- 确保 pre-commit 检查能正常通过

## 使用方法

### 基本命令
- `更新全部文档` - 启动完整的文档更新流程
- `更新需求文档` - 仅更新需求文档部分
- `更新设计文档` - 仅更新设计文档部分
- `更新项目文件` - 仅更新项目配置文件部分
- `更新用户文档` - 仅更新用户文档部分
- `更新 CICD 配置` - 仅更新 CICD 相关配置文件

### 高级命令
- `更新文档流程 <步骤>` - 执行特定步骤的文档更新
  例如：`更新文档流程 5` - 执行代码生成步骤
- `检查文档一致性` - 检查所有文档之间的一致性
- `验证文档完整性` - 验证文档是否完整
- `检查文档格式` - 检查文档的格式和规范

### 示例使用

```bash
更新文档
# 启动完整的文档更新流程

更新需求文档
# 仅更新需求文档部分

更新文档流程 7
# 执行优化循环步骤

检查文档一致性
# 检查所有文档之间的一致性
```

## 注意事项

### 准备工作
- **目录结构**：执行文档更新前，请确保项目目录结构完整，特别是 `specs/` 和 `docs/` 目录
- **依赖安装**：确保项目依赖已安装，特别是文档生成相关的依赖
- **备份**：在执行大规模文档更新前，建议备份重要文件

### 执行过程
- **用户输入**：文档更新过程中可能需要用户提供额外信息，如需求细节、设计偏好等
- **测试环境**：执行测试时，确保测试环境配置正确，依赖包已安装
- **依赖关系**：注意文档之间的依赖关系，确保更新顺序正确

### 质量保证
- **文档规范**：提交前请检查所有生成的文档是否符合项目规范和格式要求
- **测试覆盖**：运行测试时，确保测试覆盖了所有关键功能
- **代码质量**：确保所有代码和文档更改都能通过 pre-commit 检查
- **跨版本兼容性**：验证项目在多个 Python 版本下的兼容性

### 配置管理
- **版本控制**：确保所有文档更改都被正确提交到版本控制系统
- **CICD 配置**：确保 CICD 工作流文件配置正确，特别是 Python 版本矩阵和测试命令
- **覆盖率报告**：确保测试覆盖率报告能正确生成和上传到代码覆盖率服务
- **配置一致性**：确保项目配置文件之间的一致性，避免冲突

### 最佳实践
- **定期更新**：建议定期更新文档，确保文档与代码同步
- **清晰表述**：使用简洁明了的语言，避免使用模糊或歧义的表述
- **示例代码**：提供真实、可运行的示例代码，帮助用户理解
- **版本标记**：在文档中明确标记版本信息，避免混淆
- **反馈机制**：提供反馈渠道，以便向用户报告文档问题
