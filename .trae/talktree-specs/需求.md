# TalkTree 对话导航系统需求规格

## 一、核心目标

**TalkTree 要实现的目的**：

让用户能够在：

1. **多个对话框之间** - 灵活跳转、切换
2. **一个对话框中的不同话题之间** - 灵活跳转、切换
3. **一个话题下的不同问答结果之间** - 灵活导航、回溯

并且能够：

- **准确地** - 精确定位到任意对话节点
- **灵活地** - 支持多种导航方式和路径
- **继承** - 话题间可以选择性继承记忆和上下文
- **存储记忆** - 自动保存状态，支持快照和恢复

**TalkTree 不管什么**：

- ❌ AI 智能处理（这是 AI 本身的能力）
- ❌ 自然语言理解（这是 AI 本身的能力）
- ❌ 代码生成（这是 AI 本身的能力）

**TalkTree 专管什么**：

- ✅ 对话结构管理（话题树、上下文组织）
- ✅ 对话导航（跳转、切换、回溯）
- ✅ 状态保存和恢复（快照、持久化）
- ✅ 记忆继承（话题间的记忆共享规则）

## 二、核心功能需求

### 功能 1：多对话框管理

**需求描述**：
用户可以同时维护多个独立的对话框（会话），每个对话框有独立的：

- 话题树结构
- 问答历史
- 记忆存储
- 上下文状态

**功能要求**：

1. 创建新对话框
2. 列出所有对话框
3. 切换到指定对话框
4. 删除/归档对话框
5. 导出/导入对话框

### 功能 2：话题树管理

**需求描述**：
每个对话框内，用户可以创建树状结构的话题，支持：

- 根话题 → 子话题 → 孙话题的层级结构
- 每个话题有独立的问答历史和记忆
- 话题间可以有选择性地继承记忆

**功能要求**：

1. 创建话题（支持指定父话题）
2. 列出所有话题（树状展示）
3. 切换到指定话题
4. 显示当前话题路径
5. 返回父话题
6. 合并话题
7. 删除话题

### 功能 3：问答对导航

**需求描述**：
每个话题下包含多个问答对（Q\&A pairs），用户可以：

- 查看历史问答
- 跳转到特定问答对
- 搜索问答内容
- **接续历史问答继续对话**

**功能要求**：

1. 查看历史问答列表
2. 跳转到指定问答对（使用 ID）
3. 搜索包含关键词的问答
4. 显示当前问答在历史中的位置
5. **接续问答对继续对话（激活上下文）**

**使用场景**：

```
用户：查看历史
AI: **历史列表**
📍 当前: topic_001: 基础语法
📊 共 1 个话题

📁 conv_001: Python 学习
└── topic_001: 基础语法
    ├── qa_001 | 什么是变量？
    ├── qa_002 | 变量的类型有哪些？
    ...
    └── qa_005 | 什么是装饰器？

用户：tt qa use qa_005 装饰器可以嵌套使用吗？
AI: 是的，装饰器可以嵌套使用...
📎 conv_001/topic_001/qa_005 | 什么是装饰器？
💾 conv_001/topic_001/qa_011 | 装饰器可以嵌套使用吗？
```

### 功能 4：唯一 ID 系统

**需求描述**：
所有对象（对话框、话题、问答对、快照）都有全局唯一的 ID，用于：

- 精确定位和引用
- 对象间关联
- 文件存储索引
- 历史记录追踪

**ID 格式要求**：

- 对话 ID：`conv_{uuid}`
- 话题 ID：`topic_{uuid}`
- 问答 ID：`qa_{uuid}`
- 快照 ID：`snap_{uuid}`

**ID 显示要求**：

1. **创建时显示** - 创建对象时立即显示 ID
2. **响应中显示** - 每次响应包含相关对象的 ID
3. **历史记录显示** - 历史记录中每个条目都有 ID
4. **错误信息包含 ID** - 错误信息中包含相关对象的 ID

**使用场景**：

```
用户：创建话题 "装饰器"
AI: ✅ 已创建话题
💾 topic_001: 装饰器 | 0问答

用户：什么是装饰器？
AI: 装饰器是增强函数功能的函数...
💾 conv_001/topic_001/qa_001 | 什么是装饰器？

用户：tt qa show qa_001
AI: **问答详情**
📎 conv_001/topic_001/qa_001
├── 概要: 介绍装饰器的定义和基本用法
├── 涉及概念: 装饰器、函数、@语法
├── 时间: 2026-03-26 14:30
└── 回答: 略。如，装饰器是增强函数功能的函数，用于在函数执行前或执行后添加额外的功能。
```

### 功能 5：记忆和上下文管理

**需求描述**：
系统需要管理多层记忆：

- **工作记忆** - 当前对话轮的临时状态
- **短期记忆** - 当前话题的最近 N 轮对话
- **长期记忆** - 跨话题的核心概念和知识点

**记忆管理功能**：

1. **自动管理** - 系统自动提取和保存核心概念
2. **手动管理** - 用户可以添加、删除、保存、导出、导入记忆
3. **继承规则** - 子话题可以选择性继承父话题的记忆
4. **隔离规则** - 平行话题之间记忆隔离

**使用场景**：

```
# 父话题中定义核心概念
tt topic use topic_001
AI: ✅ 已使用话题
📎 topic_001: Python基础 | 0问答

用户：什么是装饰器？
AI: 装饰器是增强函数功能的函数...
💾 conv_001/topic_001/qa_001 | 什么是装饰器？
# 系统自动保存记忆：装饰器定义 (类型: core_concept)

# 保存记忆状态
tt mem save "装饰器基础知识"
AI: ✅ 已保存记忆
💾 mem_001: 装饰器基础知识 | 3键值对 | conv_001

# 列出所有记忆（跨对话显示）
tt mem ls
AI: **记忆列表**
📊 共 3 个记忆

📁 conv_001: Python学习
├── mem_001: 装饰器基础知识
└── mem_002: 用户偏好

📁 conv_002: Web开发
└── mem_003: 机器学习基础

# 使用记忆（可附带新问题）
tt mem use mem_001 装饰器在实际项目中怎么用？
AI: 基于装饰器基础知识，装饰器在实际项目中常用于...
📎 mem_001: 装饰器基础知识 | 3键值对 | conv_001
💾 conv_001/topic_001/qa_005 | 装饰器在实际项目中怎么用？

# 从其他对话导入记忆（复制语义，创建独立副本）
tt mem import mem_003 -k "ML基础"
AI: ✅ 记忆已导入
📎 mem_003: 机器学习基础 | 8键值对 | conv_002
💾 mem_004: ML基础 | 8键值对 | conv_001
# 导入后生成新的 mem_id，与原记忆独立，修改互不影响

# 导出记忆到文件（备份/分享）
tt mem export mem_001 decorator_memory.json
AI: ✅ 记忆已导出
📎 mem_001: 装饰器基础知识 | 3键值对 | conv_001 → decorator_memory.json

# 删除指定记忆
tt mem rm mem_002
AI: ✅ 已删除记忆
📎 mem_002: 用户偏好 | 2键值对 | conv_001

# 删除所有记忆
tt mem rm .
AI: ⚠️ 确认删除所有记忆？
用户：确认
AI: ✅ 已删除所有记忆

# 子话题创建时自动继承
子话题 "装饰器应用" 创建时：
📎 topic_001: Python基础 | 3问答
💾 topic_002: 装饰器应用 | 0问答
```

### 功能 6：快照管理

**需求描述**：
用户可以保存对话的快照（完整状态），仿照 Git 的 commit 机制：

- **保存范围**：整个对话的所有话题（不是单个话题）
- **包含内容**：
  - 所有话题及其问答对
  - 所有记忆状态
  - 话题树结构
  - 上下文信息

**功能要求**：

1. 保存快照（命名 + 自动生成 ID）- 保存整个对话
2. 使用快照（恢复到指定状态，可附带新问题）- 恢复整个对话
3. 查看快照详情
4. 列出所有快照
5. 删除快照
6. 快照比较
7. 导出/导入快照

**使用场景**：

```
用户：tt snap save "Python学习阶段1"
AI: ✅ 已保存快照
💾 snap_001: Python学习阶段1 | conv_001

用户：[继续学习，做了很多练习...]

用户：tt snap ls
AI: **快照列表**
📊 共 2 个快照

📁 conv_001: Python学习
├── snap_001: Python学习阶段1
│   ├── topic_001: 装饰器理论
│   │   ├── qa_001 | 什么是装饰器？

│   └── topic_002: 基础语法
│       └── qa_003 | 什么是变量？
└── snap_002: 阶段2

用户：tt snap use snap_001 装饰器可以嵌套吗？
AI: ✅ 已恢复快照并回答
📎 snap_001: Python学习阶段1 | conv_001
💾 conv_001/topic_001/qa_015 | 装饰器可以嵌套吗？

AI: **快照详情**
```

### 功能 7：自动文件持久化

**需求描述**：
系统自动将所有状态保存到文件，采用**分层保存策略**：

**P0 - 结构层**（必须保存）：

- 对话/话题/问答对的树关系
- ID、时间、继承关系

**P1 - 概要层**（按配置保存）：

- 问答对的摘要（AI 自动生成，50-100字）
- 记忆引用

**P2 - 原文层**（仅快照保存）：

- 完整的用户输入和 AI 响应
- 仅保存近期 N 轮（可配置）

**保存策略**：

| 范围     | 历史记录 | 快照 |
| ------ | ---- | -- |
| 近期 N 轮 | 概要   | 原文 |
| 更早的轮次  | 概要   | 概要 |

**保存触发条件**：

1. 创建/删除话题时
2. 添加问答对时（自动生成概要）
3. 切换话题时
4. 保存快照时（保存近期 N 轮原文）
5. 定时保存（每 15 分钟）

**文件结构**：

```
talktree-conversations/
└── conv_xxxxx/
    ├── conversation.json          # 对话主文件（P0 结构）
    ├── changelog.json             # 变更记录
    ├── topics/
    │   ├── topic_001.json         # 话题 1（包含 P0 + P1）
    │   │   └── qa_pairs/
    │   │       ├── qa_001.json    # 问答对 1（P0 + P1）
    │   │       └── qa_002.json    # 问答对 2（P0 + P1）
    │   └── topic_002.json         # 话题 2
    ├── snapshots/
    │   ├── snap_001.json          # 快照 1（P0 + P1 + P2）
    │   └── snap_002.json          # 快照 2（P0 + P1 + P2）
    └── history/
        ├── 20260326_143022_history.md  # 历史记录（P0 + P1）
        └── 20260326_150045_history.md  # 历史记录（P0 + P1）
```

### 功能 8：状态变更追踪

**需求描述**：
系统记录所有状态变更，形成完整的变更日志（changelog），包括：

- 变更时间
- 变更类型（创建话题、添加问答、切换话题等）
- 变更详情（对象 ID、名称等）

**用途**：

- 审计和回溯
- 生成历史摘要
- 支持撤销/重做（可选）

## 三、用户界面需求

### 命令风格

**要求**：使用类似 bash/git/grep 等经典命令行工具的英文命令风格，简洁、统一

**命令格式**：

```bash
tt <对象> <操作> [参数] [选项]
```

**命令分类**：

1. **对话命令**
   ```bash
   tt conv new <name>                   # 创建对话
   tt conv ls                           # 列出对话
   tt conv use <id_or_name> [新问题]     # 切换对话（可附带新问题）
   tt conv rm <id_or_name>              # 删除对话
   tt conv merge <c1> <c2>              # 合并对话
   ```
2. **话题命令**
   ```bash
   tt topic new <name> [-p <parent>]      # 创建话题
   tt topic use <name_or_id> [新问题]      # 切换话题（可附带新问题）
   tt topic ls [参数]      # 列出话题（支持 git log 风格参数，如 -5、--grep）
   tt topic rm <name_or_id>               # 删除话题
   tt topic merge <t1> <t2>               # 合并话题
   ```
3. **问答对命令**
   ```bash
   tt qa ls [参数]  # 列出问答对（支持 git log 风格参数，如 -5、--grep）
   tt qa use <qa_id> [新问题]           # 切换到问答对（激活上下文并提问）
   tt qa rm <qa_id>                    # 删除问答对
   tt qa merge <qa1> <qa2>              # 合并问答对
   ```
4. **快照命令**
   ```bash
   tt snap save <name>                  # 保存快照到系统（内部管理）
   tt snap use <id> [新问题]             # 使用快照（恢复状态，可附带新问题）
   tt snap show <id>                    # 查看快照详情
   tt snap ls [参数]           # 列出快照（支持 git log 风格参数，如 -5、--grep）
   tt snap rm <id>                      # 删除快照（使用 `.` 删除所有）
   tt snap diff <id1> <id2>             # 比较快照
   tt snap export <id> [file]           # 导出快照到文件（备份/分享）
   tt snap import <file>                # 从文件导入快照
   ```
5. **记忆命令**
   ```bash
   tt mem ls [参数]      # 列出所有记忆（支持 git log 风格参数，如 -5、--grep）
   tt mem add <key> <value>       # 添加记忆
   tt mem rm <id>                 # 删除记忆（使用 `.` 删除所有）
   tt mem save <name>             # 保存记忆状态到系统
   tt mem use <mem_id> [新问题]    # 使用记忆（可附带新问题）
   tt mem export <mem_id> [file]  # 导出记忆到文件（备份/分享）
   tt mem import <mem_id> [-k <key>]  # 从其他对话导入记忆（复制语义）
   ```

### 响应格式

#### 统一格式规范

| 对象     | 格式                                           |
| ------ | -------------------------------------------- |
| **对话** | `conv_{id}: {名称} \| {话题数}话题 {快照数}快照 {记忆数}记忆` |
| **话题** | `topic_{id}: {名称} \| {问答数}问答`                |
| **问答** | `conv_{id}/topic_{id}/qa_{id} \| {摘要}`       |
| **快照** | `snap_{id}: {名称} \| {所属对话}`                  |
| **记忆** | `mem_{id}: {名称} \| {键值对数}键值对 \| {所属对话}`      |

**分隔符规则**：

- `:` 用于分隔 ID 和名称（名称是对象的属性）
- `\|` 用于分隔 ID 和摘要/统计信息（摘要不是对象的属性）

**标记说明**：

- `💾` 表示新创建/保存的对象
- `📎` 表示被引用/继承的对象
- `📍` 表示当前激活的对象（仅 ls 命令）

#### 非 ls/show 命令

**创建操作（new/save）：**

```
AI: ✅ 已创建/保存{对象类型}
💾 {对象格式}
```

**切换/使用操作（use）：**

```
AI: ✅ 已使用{对象类型}
📎 {被引用对象格式}
💾 {新创建对象格式}（如有）
```

**删除操作（rm）：**

```
AI: ✅ 已删除{对象类型}
📎 {对象格式}
```

#### ls 命令 - 树状图

所有 `ls` 命令使用树状图格式，不包含统计信息：

```
AI: **{对象类型}列表**
📍 当前：{当前对象格式}
📊 共 {数量} 个{对象类型}

📁 {对象 1 格式}
├── {子对象 1 格式}
└── {子对象 2 格式}
```

**通用参数**（参考 git log 风格）：

所有 `ls` 命令都应遵循 git log 的参数写法（`-n 5`、`--grep "xxx"` 等），AI 应灵活理解各种合法形式。

过滤规则：`topic ls` 按话题名、`qa ls` 按问答内容、`snap ls` 按快照名、`conv ls` 按对话名、`mem ls` 按记忆键值。

#### show 命令 - 树状图

**{对象类型}详情**

**规则**：只有被查询的对象是最后一个层级、没有子层级时，才比 ls 详细；否则和 ls 一样

| 命令              | 是否有子层级 | 是否比 ls 详细 | 显示内容       |
| --------------- | ------ | --------- | ---------- |
| `tt conv show`  | ✅ 有    | ❌ 否       | 同 ls       |
| `tt topic show` | ✅ 有    | ❌ 否       | 同 ls       |
| `tt snap show`  | ✅ 有    | ❌ 否       | 同 ls       |
| `tt mem show`   | ❌ 无    | ✅ 是       | 显示键值对原文    |
| `tt qa show`    | ❌ 无    | ✅ 是       | 显示概要，不显示原文 |

**tt mem show 示例（显示键值对原文）：**

```
AI: **记忆详情**
📎 mem_001: 装饰器基础
├── decorator_definition: 装饰器是增强函数功能的函数
├── at_syntax: Python使用@表示装饰器
└── nesting_rule: 装饰器可以嵌套使用
```

**tt qa show 示例（显示概要，不显示原文）：**

```
AI: **问答详情**
📎 conv_001/topic_001/qa_001
├── 概要: 介绍变量的定义和作用
├── 涉及概念: 变量、数据类型、赋值
└── 时间: 2026-03-26 14:30
```

## 四、配置需求

### 配置文件

**要求**：

1. 使用纯 YAML 格式
2. 分组清晰
3. 包含所有可配置项

**配置项分类**：### 配置项分类

## 五、技能和规则需求

### 需要的规则文件

   - 定义状态机（话题切换、问答添加等）
   - 定义必须行为和禁止行为
2. **topic-management.md** - 话题管理规则
   - 定义话题树的组织规则
   - 定义话题创建、切换、删除的规则
   - 定义记忆继承规则
3. **memory-inheritance.md** - 记忆继承规则
   - 定义记忆分层（工作记忆、短期记忆、长期记忆）
   - 定义继承策略（全部、选择性、无）
   - 定义记忆隔离规则
4. **persistence.md** - 持久化规则
   - 定义文件存储结构
   - 定义保存触发条件
   - 定义历史记录生成规则

## 六、非功能需求

3. **加载性能** - 切换话题后 2 秒内完成加载

### 可靠性要求

1. **数据不丢失** - 任何操作后都有持久化
2. **原子操作** - 关键操作要么完全成功，要么完全失败
3. **错误恢复** - 提供回滚和恢复机制

### 易用性要求

1. **命令简洁** - 类似 git，易于记忆
2. **反馈清晰** - 操作结果明确，包含必要信息
3. **错误友好** - 错误信息清晰，提供解决建议

## 十、给 AI 的说明

**这个需求文档的用途**：

1. **不是用来生成代码的** - TalkTree 是用技能和规则实现的，不是传统代码
2. **是用来生成技能和规则的** - AI 根据这个需求文档，创建/修改：
   - 规则文件（`.md`）- 定义行为边界和约束
   - 技能文件（`SKILL.md`）- 提供具体执行逻辑

**如何实现**：

1. **规则文件** - 使用 Markdown + Mermaid 图表描述：
   - 状态机（对话状态转换）
   - 流程图（执行流程）
   - 数据流（信息流动）
   - 约束条件（必须/禁止行为）
2. **技能文件** - 使用 Markdown + 伪代码描述：
   - 职责说明
   - 命令定义
   - 执行步骤
   - 示例用法

**关键理解**：

TalkTree 的本质是\*\*"文档化的编程"\*\*：

- 规则 = 约束条件（类似代码中的常量、配置）
- 技能 = 执行逻辑（类似代码中的函数）
- 多个技能协作 = 完整的工作流（类似代码中的模块调用）

AI 通过阅读这些文档来理解如何行为，而不是执行编译后的代码。
